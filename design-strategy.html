1. 설계 목표

본 프로젝트는 대규모 React + Vite + JavaScript + CSS Modules 코드베이스를 점진적으로 이전할 수 있는 디자인 시스템 골격을 제공합니다. 다음을 동시에 달성하는 것이 목표입니다.

  • 일관성 — 색·간격·타이포·radius를 @ve/tokens 한 곳에서 정의
  • 타입 안전성 — recipe variant를 TypeScript로 추론 (RecipeVariants)
  • 런타임 최소화 — vanilla-extract로 빌드 타임 정적 CSS 추출
  • 점진적 도입 — JS 컴포넌트(.jsx)와 TS 스타일(.css.ts) 공존
  • 시각 계약 — Storybook을 컴포넌트 동작·외형의 단일 진실 공급원으로 사용

2. 핵심 원칙

Tokens first 색상, spacing, radius, typography는 반드시 @ve/tokens에서 시작한다.
Intent over implementation 컴포넌트 API는 variant(의미), size(밀도)로 의도를 표현한다.
Single source in apps 제품 앱은 임의 스타일 대신 @ve/ui를 소비한다.
Static CSS only 런타임 CSS-in-JS를 사용하지 않고 vanilla-extract 정적 추출만 허용한다.

3. 레이어 아키텍처

패키지 간 의존 방향은 단방향이며, 상위 레이어가 하위 레이어에만 의존합니다.

┌─────────────────────────────────────────────┐ │ apps/storybook, apps/web (소비 앱) │ │ — 시각 검증, 라우팅, 비즈니스 UI 조합 │ └────────────────────┬────────────────────────┘ │ import ┌────────────────────▼────────────────────────┐ │ @ve/ui (packages/ui) │ │ — React primitive, recipe, 컴포넌트 API │ └────────────────────┬────────────────────────┘ │ import vars ┌────────────────────▼────────────────────────┐ │ @ve/tokens (packages/tokens) │ │ — createGlobalTheme, 디자인 토큰, 글로벌 CSS │ └─────────────────────────────────────────────┘
레이어 책임 비책임 (하지 않을 것)
@ve/tokens 테마 변수, 글로벌 :root CSS 생성 React 컴포넌트, variant 로직
@ve/ui 재사용 primitive, recipe, export API 페이지 레이아웃, 도메인 비즈니스 로직
소비 앱 조합, 라우팅, 데이터 페칭 디자인 토큰 하드코딩, 중복 primitive 정의

4. 토큰 전략

packages/tokens/src/theme.css.ts에서 createGlobalTheme로 CSS 변수를 생성하고, vars 객체를 통해 TypeScript에서 타입 안전하게 참조합니다. 

export const vars = createGlobalTheme(":root", {
  color: { background, foreground, primary, primaryForeground, border },
  space: { x1, x2, x3, x4 },   // 4px 그리드
  radius: { sm, md },
  font: { body }
});

토큰 네이밍 규칙

  • semantic color — primary, foreground 등 역할 기반 이름 (hex 직접 참조 금지)
  • spacing scale — x1~x4 고정 스케일, 임의 px 삽입 지양
  • radius — sm, md 등 밀도별 단계

다크 모드 (예정)

createThemeContract + createTheme로 light/dark 테마를 분리하고, data-theme 또는 클래스 토글로 전환합니다. 토큰 구조는 유지하고 값만 교체합니다.

5. 컴포넌트 전략

각 primitive는 스타일 파일과 마크업 파일을 분리합니다.

파일 역할 예시
*.css.ts vanilla-extract style, recipe, variant 정의 button.css.ts
*.jsx props → className 매핑, 접근성 속성, DOM 구조 button.jsx

Button API 설계

  • variant: solid | outline — 시각적 의미
  • size: sm | md — 터치·가독성 밀도
  • defaultVariants — 미지정 시 solid + md
  • className — escape hatch (최소 사용, 앱 전용 오버라이드)
컴포넌트에 비즈니스 로직을 넣지 않습니다. 데이터 페칭, 권한, 폼 검증은 소비 앱 책임입니다.

6. 스타일링 패턴

recipe 패턴 (권장)

variant 조합이 있는 컴포넌트는 @vanilla-extract/recipes의 recipe()를 사용합니다.

const base = style({ /* 공통 */ });

export const buttonStyles = recipe({
  base,
  variants: { variant: { ... }, size: { ... } },
  defaultVariants: { variant: "solid", size: "md" }
});

// 사용: buttonStyles({ variant: "outline", size: "sm" })

style 패턴 (보조)

단일 클래스·레이아웃 유틸·앱 전용 국소 스타일은 style()만 사용합니다.

CSS Modules에서의 전환 매핑

CSS Modules vanilla-extract
Button.module.css button.css.ts
styles.primary buttonStyles({ variant: "solid" })
composes: / 중복 클래스 recipe base + variants
SCSS $color-primary vars.color.primary

7. 빌드·모듈 해석 전략

워크스페이스 패키지는 dist-first 정책을 따릅니다.

환경 @ve/tokens 해석 빌드 선행 필요
IDE / tsc --noEmit packages/tokens/dist/ 예
Storybook (Vite alias) packages/tokens/src/ 아니오 (dev)
프로덕션 번들 dist/ via package exports 예
운영 규칙: 클론 직후 pnpm build를 실행한다. Turbo build 태스크는 dependsOn: ["^build"]로 의존 패키지 순서를 보장한다.

빌드 도구

  • tsup — ESM + d.ts 생성
  • @vanilla-extract/esbuild-plugin — .css.ts → 정적 CSS 추출
  • @vanilla-extract/vite-plugin — Storybook·Vite 앱 dev/build

8. 소비 앱 연동 전략

의존성

{
  "dependencies": {
    "@ve/ui": "workspace:*",
    "@ve/tokens": "workspace:*"
  }
}

앱 부트스트랩

// main.jsx — 글로벌 테마 CSS 주입
import "@ve/tokens";
import { Button } from "@ve/ui";

Strangler Fig (점진 교체)

  1. 신규 화면·기능부터 @ve/ui 적용
  2. 기존 CSS Modules 화면은 수정 시점에만 교체
  3. 교체 전·후 동일 스토리를 Storybook에 등록해 회귀 기준 확보

9. 품질·계약 전략

  • Storybook — variant·size 조합의 시각 계약, controls로 prop 탐색
  • check-types — 패키지별 tsc --noEmit, recipe 타입 추론 검증
  • Turbo pipeline — build → lint → check-types → test
  • 회귀 방지 — (선택) Chromatic 등 시각 스냅샷

컴포넌트 변경 시 스토리 업데이트를 PR 체크리스트에 포함합니다.
