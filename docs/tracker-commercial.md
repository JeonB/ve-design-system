# 설계서: 상용 수준 이슈 트래커 (Jira Software 기준)

> 작성일: 2026-09-26  
> 대상: `apps/tracker`  
> 선행: [`jira-console.md`](./jira-console.md)  
> 기간: 2026-09-26 ~ 2026-09-30

Jira Software에서 팀이 매일 여는 화면은 세 가지다. **백로그**(스프린트에 넣기), **액티브 스프린트 보드**(상태 컬럼으로 옮기기), **이슈 상세**(설명·필드·댓글·활동). 마켓플레이스, JQL, 권한 스킴, 자동화 규칙은 이번 범위가 아니다.

## 지금 못 쓰는 이유

| 갭 | Jira에서 하는 일 | 현재 |
|----|------------------|------|
| 저장 | 이슈가 남는다 | 새로고침하면 시드로 돌아간다 |
| 활동 | 누가 상태·담당을 바꿨는지 남는다 | 댓글만 있다 |
| 스프린트 | 백로그와 진행 중 일을 나눈다 | 모든 이슈가 한 보드에 있다 |
| 보드 | 카드를 컬럼으로 끌어 옮긴다 | Select만 있다 |
| 이슈 깊이 | 포인트, 라벨, 하위 작업 | 제목·설명·담당뿐 |
| 찾기 | 키·요약·저장된 필터 | 요약 문자열만 |

## 범위

1. 로컬 저장소에 워크스페이스를 남긴다. 깨진 데이터는 시드로 되돌린다.
2. 필드 변경과 댓글은 이슈 활동으로 남긴다.
3. 프로젝트마다 스프린트를 만들고, 시작하고, 완료한다. 보드는 **활성 스프린트**만 보여 준다.
4. 보드 카드는 상태 컬럼으로 드래그한다. 빠른 필터는 내 이슈와 텍스트다.
5. 스토리 포인트, 라벨, 상위 이슈(하위 작업)를 둔다.
6. 이슈 목록은 키·요약·라벨을 찾고, 필터를 저장한다.

비목표: JQL, 첨부 파일, 실시간 동시 편집, 권한, 이메일 알림, 워크플로 디자이너.

## 구현 메모 (2026-09-30)

이슈 목록 검색은 키, 요약, 라벨을 함께 본다. 저장 필터는 프로젝트별로 이름과 조건(검색어, 유형, 상태, 담당)을 워크스페이스에 남긴다. 필터 필드가 없는 이전 저장본은 빈 목록으로 읽는다. 도메인 테스트는 `pnpm --filter tracker test`로 확인한다.
